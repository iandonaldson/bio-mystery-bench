## 1. Why a Provider Abstraction?

Before this change, `harness/agent.py` imported `anthropic` directly and
`harness/scorer.py` held a reference to `anthropic.Anthropic`. Adding a second
provider would have required forking both files and duplicating the entire agent
loop. Instead, the harness was refactored around a single concept:

> **The Anthropic message format is the canonical internal representation.
> Each provider subclass handles its own wire-format conversion.**

This means the agent loop, logger, scorer, and cost tracker never need to know
which provider is in use. The conversion layer sits entirely inside `harness/llm.py`.

The design follows the **Abstract Base Class (ABC)** pattern from Python's `abc`
module: `Provider` defines the contract; `AnthropicProvider` and `OpenAIProvider`
fulfil it.

```
run_eval.py
    └─► build_provider(...)          harness/llm.py
          ├─► AnthropicProvider      (Anthropic SDK)
          └─► OpenAIProvider         (OpenAI SDK ← also Groq, Cerebras, Ollama)
                │
                ▼ both return LLMResponse
    └─► AgentRun(client=provider)    harness/agent.py
    └─► score_answer(..., client)    harness/scorer.py
```

> **📦 Python ABC (`abc` module)**
> An Abstract Base Class defines one or more `@abstractmethod` methods that
> subclasses *must* implement. Attempting to instantiate a subclass that hasn't
> implemented all abstract methods raises `TypeError` at runtime. This gives
> a clear, enforceable contract without the overhead of a protocol library.
> Further reading: [Python `abc` module docs](https://docs.python.org/3/library/abc.html)

## 2. The Canonical Internal Format

**File:** [harness/llm.py](../../harness/llm.py)

Three dataclasses form the "internal language" that all other modules speak.
They are modelled on the Anthropic SDK's response shapes because the harness
was originally Anthropic-only; the OpenAI adapter converts *to* this format.

### 2.1 LLMToolCall

```python
# harness/llm.py
@dataclass
class LLMToolCall:
    id: str               # unique per call, e.g. "toolu_01XYZ" or "call_a3f1b2c4"
    name: str             # "bash" or "abort"
    input: dict[str, Any] # parsed JSON from the model, e.g. {"command": "ls /"}
```

`id` must be echoed back in the `tool_result` message so the model can match
results to the call that produced them. For Anthropic this is a string like
`toolu_01XYZ`; for OpenAI it is `call_<hex>`. The harness uses whichever the
provider returns.

### 2.2 LLMUsage

```python
# harness/llm.py
@dataclass
class LLMUsage:
    input_tokens: int = 0        # new, non-cached input tokens billed at full rate
    output_tokens: int = 0       # generated tokens (most expensive)
    cache_read_tokens: int = 0   # input tokens served from Anthropic prompt cache (~10% rate)
```

The three fields map directly onto `CostTracker.add()`. OpenAI-compatible
providers report `prompt_tokens` (= `input_tokens`) and `completion_tokens`
(= `output_tokens`); `cache_read_tokens` maps to
`usage.prompt_tokens_details.cached_tokens` when available.

### 2.3 LLMResponse

```python
# harness/llm.py
@dataclass
class LLMResponse:
    stop_reason: str                          # "end_turn" | "tool_use"
    text: str                                 # joined text from all text blocks
    tool_calls: list[LLMToolCall] = field(default_factory=list)
    usage: LLMUsage = field(default_factory=LLMUsage)
    raw_content: Any = None                   # Anthropic-format list; stored back in messages
```

`raw_content` is the piece that makes the message history round-trip correctly.
The agent loop appends each response's `raw_content` directly to `self.messages`
as the `"content"` value of the assistant turn. For Anthropic responses this is
the SDK's native `content` list (Pydantic objects). For OpenAI responses it is
a list of plain dicts in the same shape (e.g.
`[{"type": "tool_use", "id": "...", "name": "bash", "input": {...}}]`).
The `anthropic_to_openai_messages()` converter handles both forms when building
the next OpenAI request.

## 3. Entry Point — `scripts/run_eval.py`

**File:** [scripts/run_eval.py](../../scripts/run_eval.py)

### 3.1 Provider CLI flags

Four new `@click.option` decorators were added alongside the existing ones:

```python
# scripts/run_eval.py
@click.option("--provider", default="anthropic",
              type=click.Choice(["anthropic", "openai", "ollama", "groq", "azure"]),
              help="LLM provider.")
@click.option("--api-base-url", default=None,
              help="Base URL for OpenAI-compatible endpoints.")
@click.option("--api-key", default=None,
              help="API key (overrides env var).")
@click.option("--judge-model", default=None,
              help="Model for LLM-as-judge scoring.")
```

`--provider groq` is the only named non-OpenAI alternative besides `anthropic`;
it is handled identically to `--provider openai` inside `build_provider()` but
has a hardcoded default base URL (see §12).

### 3.2 API key resolution (`_resolve_api_key`)

```python
# scripts/run_eval.py
_API_KEY_ENV_VARS = {
    "anthropic": "ANTHROPIC_API_KEY",
    "openai":    "OPENAI_API_KEY",
    "groq":      "GROQ_API_KEY",
    "azure":     "AZURE_AI_API_KEY",
}

def _resolve_api_key(provider: str, explicit_key: str | None) -> str | None:
    if explicit_key:
        return explicit_key
    if provider == "ollama":
        return os.environ.get("OLLAMA_API_KEY", "ollama")   # Ollama ignores the key
    env_var = _API_KEY_ENV_VARS.get(provider, "LLM_API_KEY")
    return os.environ.get(env_var)
```

Each provider reads its own named environment variable. The `.env` file at the
project root (loaded by `python-dotenv`) is the standard place to put keys:

```
# .env
ANTHROPIC_API_KEY=sk-ant-...
GROQ_API_KEY=gsk_...
CEREBRAS_API_KEY=csk-...
```

`python-dotenv` loads `.env` at the top of `run_eval.py` via:

```python
from dotenv import load_dotenv
load_dotenv(override=True)
```

`override=True` means the `.env` file's values override any shell environment
variables already set, which is important in VS Code terminals where the shell
may have stale keys exported.

> **📦 `python-dotenv`**
> `load_dotenv()` reads a `.env` file and injects its `KEY=VALUE` pairs into
> `os.environ` so they are available to `os.environ.get()`. This keeps secrets
> out of the codebase while still making them available to the process at
> runtime. Never commit `.env` to version control.
> Further reading: [python-dotenv docs](https://saurabh-kumar.com/python-dotenv/)

### 3.3 Per-model cost lookup (`_MODEL_COSTS`)

Before the multi-provider work, cost rates came from `RunConfig`
(`cost_per_million_input/output`) which were hard-coded for Claude Sonnet.
That still works for Anthropic, but Groq and Cerebras models have different
rates. A lookup table was added:

```python
# scripts/run_eval.py
_MODEL_COSTS: dict[str, tuple[float, float]] = {
    # Anthropic
    "claude-sonnet-4-6":                (3.0,    15.0),
    "claude-opus-4-7":                  (15.0,   75.0),
    "claude-haiku-4-5-20251001":        (0.8,     4.0),
    # Groq (Llama family)
    "llama-3.3-70b-versatile":          (0.59,    0.79),
    "llama-3.1-8b-instant":             (0.05,    0.08),
    "qwen3-32b":                        (0.29,    0.59),
    # Azure AI Foundry — serverless (MaaS) pay-per-token rates
    "Phi-4":                            (0.125,   0.50),
    "Phi-4-mini":                       (0.025,   0.095),
    "Phi-4-mini-reasoning":             (0.025,   0.095),
    "Meta-Llama-3.3-70B-Instruct":      (0.59,    0.79),
    "Meta-Llama-3.1-8B-Instruct":       (0.05,    0.10),
    "Mistral-Large-2411":               (2.0,     6.0),
    "Mistral-Nemo":                     (0.13,    0.13),
    "Cohere-command-r-plus-08-2024":    (2.5,    10.0),
}
```

Models not in the table (including all Ollama models) default to `0.0/0.0`,
which means the cost tracker counts tokens but shows `$0.00`.

> **Adding a new model:** Find its pricing at [ai.azure.com/explore/models](https://ai.azure.com/explore/models),
> [groq.com/pricing](https://groq.com/pricing), or your provider's pricing page.
> Add one line to `_MODEL_COSTS` — no other code changes needed.

### 3.4 Building a `CostTracker` with provider-aware rates

```python
# scripts/run_eval.py  (inside main())
if provider == "ollama":
    cost_input, cost_output = 0.0, 0.0
elif model in _MODEL_COSTS:
    cost_input, cost_output = _MODEL_COSTS[model]
elif provider == "anthropic":
    cost_input, cost_output = config.cost_per_million_input, config.cost_per_million_output
else:
    cost_input, cost_output = 0.0, 0.0

cost_tracker = CostTracker(
    cost_per_million_input=cost_input,
    cost_per_million_output=cost_output,
    max_session_cost_usd=max_cost,
)
```

The three-branch priority is:
1. Ollama → always free (local inference)
2. Known model name → use the lookup table
3. Anthropic with an unknown model → fall back to `RunConfig`'s defaults
4. Unknown provider + unknown model → `$0.00` (counts tokens silently)

### 3.5 Factory call: `build_provider`

```python
# scripts/run_eval.py  (inside main(), after user confirms cost)
resolved_base_url = api_base_url or _DEFAULT_BASE_URLS.get(provider)
resolved_key = _resolve_api_key(provider, api_key)
resolved_judge = judge_model or (
    "claude-haiku-4-5-20251001" if provider == "anthropic" else model
)
client = build_provider(provider, resolved_key, resolved_base_url, resolved_judge)
```

`_DEFAULT_BASE_URLS` maps named providers to their base endpoints so the user
does not have to pass `--api-base-url` for Groq:

```python
_DEFAULT_BASE_URLS = {
    "groq":   "https://api.groq.com/openai/v1",
    "ollama": "http://localhost:11434/v1",
}
```

For `provider == "anthropic"`, `base_url` is `None` (ignored by `AnthropicProvider`).
For `provider == "groq"`, it becomes `"https://api.groq.com/openai/v1"` and is passed
to `OpenAIProvider`.

The `judge_model` determines which model is used for LLM-as-judge scoring:
- Anthropic: default to Haiku (cheap, fast)
- Any other provider: default to the same model being evaluated (avoids needing
  a second API key for Groq/Cerebras judge calls)

### 3.6 Per-attempt cost snapshot

To record how much each individual attempt cost, the total cost is snapshotted
before the attempt and subtracted after:

```python
# scripts/run_eval.py  (_run_problem, inside the attempt loop)
cost_before = cost_tracker.total_cost_usd

# ... TrajectoryLogger + Container + AgentRun.run() here ...

attempt_record: dict = {
    "status":       result.status,
    "correct":      correct,
    "steps":        result.steps,
    "wall_seconds": round(result.wall_seconds, 1),
    "predicted":    predicted[:300],
    "cost_usd":     round(cost_tracker.total_cost_usd - cost_before, 6),
}
```

`cost_tracker` is a shared object across all problems and all attempts in a
session (it enforces the session-level `max_session_cost_usd` cap). The delta
`total_cost_usd - cost_before` isolates the cost of just this one attempt.

The `cost_usd` field is displayed in the per-problem results table printed at
the end of the run (see §11 for the `_print_summary` table).

## 4. The Provider ABC — `harness/llm.py`

**File:** [harness/llm.py](../../harness/llm.py)

### 4.1 Abstract `Provider` base class

```python
# harness/llm.py
from abc import ABC, abstractmethod

class Provider(ABC):
    """Abstract LLM provider. Subclasses handle wire-format conversion."""

    judge_model: str = ""   # set by build_provider(); read by scorer._llm_judge()

    @abstractmethod
    def chat(
        self,
        model: str,
        system: str,
        messages: list[dict],
        tools: list[dict],
        max_tokens: int,
    ) -> LLMResponse: ...
```

`chat()` is the only method the rest of the harness calls. Its signature
mirrors the Anthropic `messages.create()` call, which makes the
`AnthropicProvider` implementation trivial and the `OpenAIProvider`
implementation purely about format conversion.

`judge_model` is a class-level attribute (not a constructor argument) set by
`build_provider()` after instantiation. The scorer reads it via
`getattr(client, "judge_model", "")`.

### 4.2 Factory function `build_provider`

```python
# harness/llm.py
def build_provider(
    provider: str,
    api_key: str,
    base_url: Optional[str] = None,
    judge_model: str = "",
) -> Provider:
    if provider == "anthropic":
        p = AnthropicProvider(api_key=api_key)
    else:
        p = OpenAIProvider(api_key=api_key, base_url=base_url)
    p.judge_model = judge_model
    return p
```

Note that `"groq"` is not a special case here — it falls into the `else` branch
and becomes an `OpenAIProvider` with a Groq base URL. All OpenAI-compatible
endpoints (Groq, Cerebras, Ollama, Azure OpenAI, Together AI) use this same
path.

## 5. AnthropicProvider — `harness/llm.py`

### 5.1 Constructor

```python
# harness/llm.py
class AnthropicProvider(Provider):
    def __init__(self, api_key: str) -> None:
        import anthropic
        self._client = anthropic.Anthropic(api_key=api_key)
```

The `import anthropic` is deferred inside `__init__` so the `openai` package
is never imported unless `OpenAIProvider` is instantiated, and vice versa.
This keeps startup fast and avoids import errors when only one SDK is installed.

### 5.2 `chat()` method

```python
# harness/llm.py
def chat(self, model, system, messages, tools, max_tokens) -> LLMResponse:
    system_with_cache = [
        {"type": "text", "text": system, "cache_control": {"type": "ephemeral"}}
    ]
    response = self._client.messages.create(
        model=model,
        max_tokens=max_tokens,
        system=system_with_cache,
        messages=messages,
        tools=tools,
    )
    return _anthropic_response_to_llm_response(response)
```

The `cache_control: {"type": "ephemeral"}` annotation wraps the system prompt
and tells Anthropic to cache its KV (key-value) representation between API
calls. Because the system prompt is hundreds of tokens and stays identical
across all steps of a run, this saves roughly 50% on input token costs for
multi-step runs.

> **📦 Anthropic prompt caching**
> Anthropic's prompt cache stores the KV (key-value) intermediate state of
> specific prompt blocks between API calls. The `cache_control: ephemeral`
> annotation marks a block as cacheable for up to 5 minutes. Cache hits are
> billed at ~10% of the normal input token rate.
> Further reading: [Anthropic prompt caching guide](https://docs.anthropic.com/en/docs/build-with-claude/prompt-caching)

### 5.3 `_anthropic_response_to_llm_response()`

```python
# harness/llm.py
def _anthropic_response_to_llm_response(response: Any) -> LLMResponse:
    content = response.content   # list of TextBlock / ToolUseBlock Pydantic objects
    text_parts = []
    tool_calls = []

    for block in content:
        btype = block.type if hasattr(block, "type") else block.get("type")
        if btype == "text":
            text_parts.append(block.text if hasattr(block, "text") else block.get("text", ""))
        elif btype == "tool_use":
            tool_calls.append(LLMToolCall(
                id=block.id if hasattr(block, "id") else block["id"],
                name=block.name if hasattr(block, "name") else block["name"],
                input=block.input if hasattr(block, "input") else block["input"],
            ))

    usage = response.usage
    cache_read = getattr(usage, "cache_read_input_tokens", 0) or 0
    return LLMResponse(
        stop_reason=response.stop_reason,
        text="\n".join(text_parts),
        tool_calls=tool_calls,
        usage=LLMUsage(
            input_tokens=usage.input_tokens,
            output_tokens=usage.output_tokens,
            cache_read_tokens=cache_read,
        ),
        raw_content=content,   # ← kept as-is; Pydantic objects are fine here
    )
```

The dual `hasattr / .get()` pattern in the block accessors handles both
Pydantic model instances (from the live Anthropic SDK) and plain dicts (from
test mocks and serialised trajectories). This makes the converter robust to
both production use and unit testing.

## 6. OpenAIProvider — `harness/llm.py`

### 6.1 Constructor

```python
# harness/llm.py
class OpenAIProvider(Provider):
    def __init__(self, api_key: str, base_url: Optional[str] = None) -> None:
        import openai
        self._client = openai.OpenAI(api_key=api_key, base_url=base_url)
```

`openai.OpenAI` accepts a `base_url` that replaces the default
`https://api.openai.com/v1`. Setting it to `https://api.groq.com/openai/v1`
(or `http://localhost:11434/v1` for Ollama) routes all requests to that
endpoint while reusing the same SDK. This is why a single `OpenAIProvider`
class serves Groq, Cerebras, Ollama, and any other OpenAI-API-compatible
service.

> **📦 OpenAI-compatible API**
> Many LLM providers implement the same REST API contract as OpenAI's chat
> completions endpoint (`POST /v1/chat/completions`). This includes Groq
> (LPU-based inference), Cerebras (wafer-scale chips), Ollama (local
> models), Azure OpenAI, Together AI, and Mistral. Any provider that
> supports this contract can use `OpenAIProvider` with just a different
> `base_url` and `api_key`.
> Further reading: [OpenAI chat completions API spec](https://platform.openai.com/docs/api-reference/chat)

### 6.2 `chat()` method and the `BadRequestError` recovery path

```python
# harness/llm.py
def chat(self, model, system, messages, tools, max_tokens) -> LLMResponse:
    import openai as _openai
    oai_messages = anthropic_to_openai_messages(messages, system)
    oai_tools = [anthropic_tool_to_openai(t) for t in tools] if tools else None
    kwargs: dict[str, Any] = dict(
        model=model,
        messages=oai_messages,
        max_tokens=max_tokens,
    )
    if oai_tools:
        kwargs["tools"] = oai_tools
    try:
        response = self._client.chat.completions.create(**kwargs)
        return openai_response_to_llm_response(response)
    except _openai.BadRequestError as e:
        # Groq returns 400 when Llama emits malformed tool calls in its output.
        # The failed generation is in e.body["error"]["failed_generation"].
        error_body = getattr(e, "body", None) or {}
        failed_gen = (error_body.get("error") or {}).get("failed_generation", "")
        tool_call = _parse_llama_text_tool_call(failed_gen)
        if tool_call:
            return LLMResponse(
                stop_reason="tool_use",
                text="",
                tool_calls=[tool_call],
                usage=LLMUsage(),
                raw_content=[{
                    "type": "tool_use",
                    "id": tool_call.id,
                    "name": tool_call.name,
                    "input": tool_call.input,
                }],
            )
        raise   # re-raise if we couldn't parse a tool call — let the agent loop handle it
```

The happy path:
1. Convert Anthropic-format history and tools to OpenAI wire format.
2. Call `chat.completions.create()`.
3. Normalise the response back to `LLMResponse`.

The recovery path handles a Groq-specific failure mode described in §7.

### 6.3 `anthropic_to_openai_messages()`

This is the most complex conversion function. It translates the internal
Anthropic message history into the OpenAI `messages` list.

```python
# harness/llm.py
def anthropic_to_openai_messages(messages: list[dict], system: str) -> list[dict]:
    result: list[dict] = []
    if system:
        result.append({"role": "system", "content": system})
    ...
```

The system prompt is prepended as `{"role": "system", ...}`. An empty system
string is omitted entirely because some Ollama models reject an empty system
message.

The function handles four block types, each with a different conversion:

#### User text blocks

```python
# harness/llm.py  (inside anthropic_to_openai_messages, user role branch)
for block in items:
    btype = block.get("type") if isinstance(block, dict) else getattr(block, "type", None)
    if btype == "tool_result":
        tool_results.append(block)
    elif btype == "text":
        text = block.get("text", "") ...
        if text:
            text_parts.append(text)

if text_parts:
    result.append({"role": "user", "content": "\n".join(text_parts)})
```

The `cache_control` key present on some text blocks (from the initial user
message in `agent.py`) is silently dropped — OpenAI has no equivalent.

#### Tool result blocks

In the Anthropic format, tool results are nested as `type: tool_result` blocks
inside a user turn. OpenAI requires them as separate top-level messages with
`role: tool`:

```python
# harness/llm.py
for tr in tool_results:
    tid = tr.get("tool_use_id", "") ...
    tc = tr.get("content", "") ...
    result.append({"role": "tool", "tool_call_id": tid, "content": tc or ""})
```

This means one Anthropic user message containing N tool results becomes N
separate OpenAI `role: tool` messages.

#### Assistant text blocks

```python
# harness/llm.py  (assistant role branch)
asst: dict[str, Any] = {
    "role": "assistant",
    "content": "\n".join(text_parts) if text_parts else None,
}
if tool_calls_oai:
    asst["tool_calls"] = tool_calls_oai
result.append(asst)
```

`"content": None` is used (rather than omitting the key) when the assistant
turn has tool calls but no text. Some Ollama models reject a missing `content`
key on assistant messages.

#### Assistant tool-use blocks

```python
# harness/llm.py  (inside assistant role loop)
elif btype == "tool_use":
    bid = block.get("id") ...
    bname = block.get("name") ...
    binput = block.get("input") ...
    tool_calls_oai.append({
        "id": bid,
        "type": "function",
        "function": {
            "name": bname,
            "arguments": json.dumps(binput),  # ← must be a JSON string, not a dict
        },
    })
```

The `arguments` field must be a JSON-encoded *string*, not a Python dict —
this is an OpenAI API requirement. The dual `block.get() / getattr()` pattern
again handles both Pydantic objects (live SDK responses stored in `raw_content`)
and plain dicts (deserialized from test fixtures or stored `raw_content`).

### 6.4 `anthropic_tool_to_openai()`

```python
# harness/llm.py
def anthropic_tool_to_openai(tool: dict) -> dict:
    return {
        "type": "function",
        "function": {
            "name": tool["name"],
            "description": tool.get("description", ""),
            "parameters": tool.get("input_schema", {}),
        },
    }
```

The Anthropic tool definition uses `input_schema` for the JSON Schema
describing the tool's inputs. OpenAI calls the same field `parameters`.
Everything else (`name`, `description`, the schema body itself) is identical
between the two formats.

### 6.5 `openai_response_to_llm_response()`

```python
# harness/llm.py
def openai_response_to_llm_response(response: Any) -> LLMResponse:
    choice = response.choices[0]
    msg = choice.message
    finish_reason = choice.finish_reason

    stop_reason = "tool_use" if finish_reason == "tool_calls" else "end_turn"
    text = msg.content or ""
    tool_calls: list[LLMToolCall] = []
    raw_content: list[dict] = []

    if text:
        raw_content.append({"type": "text", "text": text})

    for tc in (msg.tool_calls or []):
        try:
            input_dict = json.loads(tc.function.arguments)
        except (json.JSONDecodeError, AttributeError):
            input_dict = {}
        tool_calls.append(LLMToolCall(id=tc.id, name=tc.function.name, input=input_dict))
        raw_content.append({
            "type": "tool_use",
            "id": tc.id,
            "name": tc.function.name,
            "input": input_dict,
        })
    ...
```

The `raw_content` list is built as plain dicts in Anthropic format. This is
what gets stored in `self.messages` by the agent loop, so the next call to
`anthropic_to_openai_messages()` can convert it back to OpenAI format without
needing to know it originally came from an OpenAI response.

Cache-read tokens are extracted from the nested `prompt_tokens_details` field:

```python
    usage = response.usage
    cache_read = 0
    if hasattr(usage, "prompt_tokens_details") and usage.prompt_tokens_details:
        cache_read = getattr(usage.prompt_tokens_details, "cached_tokens", 0) or 0
```

This field is only populated by providers that support caching (Anthropic via
the OpenAI-compat endpoint, some Azure OpenAI configurations). For Groq and
Cerebras it is always 0.

## 7. Llama Text-Format Tool Call Recovery

### 7.1 The two failure modes

Llama-family models (including `llama-3.3-70b-versatile` on Groq) sometimes
emit tool calls as raw text rather than using the structured `tool_calls` field
in the OpenAI response. This happens in two distinct ways:

**Mode 1 — end-turn text response (silent):**
The model sets `finish_reason = "stop"` and puts the tool call inline in
`message.content`:
```
<function/bash>{"command": "ls /workspace/data"}
```
The OpenAI SDK treats this as ordinary text; no `tool_calls` field is populated.

**Mode 2 — malformed generation caught by Groq (noisy):**
The model generates a syntactically invalid tool call:
```
<function=bash[]{"command": "samtools view -c file.bam"}></function>
```
Groq's server detects the invalid format and returns a `400 Bad Request` error.
The error body contains the raw failed generation in
`error.body["error"]["failed_generation"]`.

Both modes require the same solution: parse the embedded JSON from the text
and synthesise a proper `LLMToolCall`.

### 7.2 `_parse_llama_text_tool_call()`

```python
# harness/llm.py
def _parse_llama_text_tool_call(text: str) -> Optional[LLMToolCall]:
    """Parse Llama-family text-format tool calls.

    Handles:
      <function/bash>{"command": "..."}                (end_turn text)
      <function=bash[]{"command": "..."}></function>   (failed_generation body)
    """
    m = re.search(r"<function[/=](\w+)", text)   # capture tool name
    if not m:
        return None
    name = m.group(1)

    json_start = text.find("{", m.start())   # find opening brace
    if json_start == -1:
        return None

    # Brace-counting to find the matching close brace (handles nested JSON)
    depth = 0
    json_end = json_start
    for i, ch in enumerate(text[json_start:], json_start):
        if ch == "{":
            depth += 1
        elif ch == "}":
            depth -= 1
            if depth == 0:
                json_end = i + 1
                break

    try:
        input_dict = json.loads(text[json_start:json_end])
    except json.JSONDecodeError:
        return None

    return LLMToolCall(
        id=f"call_{uuid.uuid4().hex[:8]}",   # synthetic ID; echoed back in tool_result
        name=name,
        input=input_dict,
    )
```

The brace-counting loop is necessary because the `command` argument can itself
contain `{` and `}` characters (e.g., awk scripts like
`awk '{print $1}'`). A simple `text.find("}")` would stop at the first close
brace inside the command string, producing a truncated and invalid JSON snippet.

The synthetic `id` uses `uuid.uuid4().hex[:8]` — 8 hex characters gives
268 million unique values, more than enough for a single run's tool calls.

### 7.3 End-turn text fallback (path 1)

This path runs at the end of `openai_response_to_llm_response()`, after the
normal `msg.tool_calls` loop has been exhausted:

```python
# harness/llm.py  (openai_response_to_llm_response, end of function)
# Fallback: some Llama models output tool calls as text rather than
# using the structured tool_calls field.
if not tool_calls and text:
    text_tc = _parse_llama_text_tool_call(text)
    if text_tc:
        stop_reason = "tool_use"
        tool_calls.append(text_tc)
        raw_content = [{
            "type": "tool_use",
            "id": text_tc.id,
            "name": text_tc.name,
            "input": text_tc.input,
        }]
```

When triggered, `stop_reason` is overridden from `"end_turn"` to `"tool_use"`,
which causes the agent loop to dispatch the extracted tool call exactly as if
the model had used the structured format.

### 7.4 Rate-limit retry logging

When `OpenAIProvider.chat()` catches a `RateLimitError` (429), it waits and retries
(up to three times with 60/120/240 s delays). Each wait now also emits a
`rate_limit_retry` record to the trajectory JSONL via the optional `logger` parameter:

```python
if logger is not None:
    logger.log("rate_limit_retry", {
        "attempt": attempt + 1,   # 1-based
        "wait_seconds": delay,
        "provider": "openai",
    })
```

`AgentRun._loop()` passes `logger=self.logger` on every `client.chat()` call so retry
events are always captured for OpenAI-compatible providers. `AnthropicProvider.chat()`
accepts the parameter but ignores it (Anthropic SDK handles retries internally).

### 7.5 BadRequestError recovery (path 2)

This path is the `except` clause inside `OpenAIProvider.chat()`:

```python
# harness/llm.py  (OpenAIProvider.chat, except clause)
except _openai.BadRequestError as e:
    error_body = getattr(e, "body", None) or {}
    failed_gen = (error_body.get("error") or {}).get("failed_generation", "")
    tool_call = _parse_llama_text_tool_call(failed_gen)
    if tool_call:
        return LLMResponse(
            stop_reason="tool_use",
            text="",
            tool_calls=[tool_call],
            usage=LLMUsage(),   # no token usage available on error path
            raw_content=[{
                "type": "tool_use",
                "id": tool_call.id,
                "name": tool_call.name,
                "input": tool_call.input,
            }],
        )
    raise   # unrecognised 400 — propagate to agent error handler
```

If `_parse_llama_text_tool_call` finds nothing in the failed generation
(e.g., the 400 was for a different reason), the exception is re-raised and
caught by the agent loop's `except Exception` clause, which logs an `error`
status and terminates the attempt.

## 8. Agent Loop — `harness/agent.py`

**File:** [harness/agent.py](../../harness/agent.py)

### 8.1 Accepting a `Provider` instead of `anthropic.Anthropic`

The only change to `AgentRun.__init__` was the type annotation:

```python
# harness/agent.py  (before)

```

No runtime behaviour changed. `Provider` is an ABC, so Python's duck-typing
means any object with a `chat()` method that returns `LLMResponse` will work.

### 8.2 Calling `client.chat()`

Before the refactor, the agent called `self.client.messages.create()` directly
with Anthropic SDK kwargs. After the refactor it calls the normalised interface:

```python
# harness/agent.py  (_loop)
response = self.client.chat(
    model=self.config.model,
    system=self.system_prompt,
    messages=self.messages,
    tools=[BASH_TOOL, ABORT_TOOL],
    max_tokens=self.config.max_tokens_per_step,
)
```

The `system_with_cache` construction (wrapping the system prompt with
`cache_control`) was moved inside `AnthropicProvider.chat()` so the agent
loop is provider-agnostic.

### 8.3 Consuming `LLMResponse`

```python
# harness/agent.py  (_loop, after chat() call)
step_input = response.usage.input_tokens
step_output = response.usage.output_tokens
step_cache = response.usage.cache_read_tokens

self.input_tokens += step_input
self.output_tokens += step_output
self.cache_read_tokens += step_cache
self.cost_tracker.add(step_input, step_output, step_cache)

self.logger.log("assistant", {
    "stop_reason": response.stop_reason,
    "reasoning":   response.text,
    "content":     response.raw_content,
    "usage":       {"input": step_input, "output": step_output, "cache_read": step_cache},
})

self.messages.append({"role": "assistant", "content": response.raw_content})
self.steps += 1
```

Three things happen with `raw_content`:
1. It is logged to the trajectory JSONL (for human review via `trajectory_to_md.py`)
2. It is appended to `self.messages` so the provider sees the full history on the next call
3. When the next call is to `OpenAIProvider`, `anthropic_to_openai_messages()` reads
   `raw_content` dicts and converts them to OpenAI tool_calls format

Tool dispatch then iterates over `response.tool_calls` (the normalised `LLMToolCall`
list) rather than the provider-specific content blocks:

```python
# harness/agent.py  (_loop, tool dispatch)
if response.stop_reason == "tool_use":
    tool_results = []
    for tool_call in response.tool_calls:    # ← LLMToolCall dataclass, not Pydantic
        if tool_call.name == "abort":
            ...
        if tool_call.name == "bash":
            command = tool_call.input.get("command", "")
            stdout, stderr, rc = self.container.exec_command(command, ...)
            tool_results.append({
                "type":        "tool_result",
                "tool_use_id": tool_call.id,  # echoed back for model to match
                "content":     result_text,
                "is_error":    rc != 0,
            })
    self.messages.append({"role": "user", "content": tool_results})
```

Note the `"is_error": rc != 0` field: this is Anthropic-specific and is silently
stripped by `anthropic_to_openai_messages()` when sending to OpenAI (no equivalent
field exists in the OpenAI `role: tool` message format).

## 9. Scorer — `harness/scorer.py`

**File:** [harness/scorer.py](../../harness/scorer.py)

### 9.1 Dual-path `_llm_judge`

Before the refactor, `_llm_judge` held a direct reference to `anthropic.Anthropic`
and called `client.messages.create()`. After the refactor it supports both the
new `Provider` ABC and the old raw SDK client (for backwards compatibility with
any code calling `score_answer` outside the main harness):

```python
# harness/scorer.py
def _llm_judge(predicted: str, rubric: str, client: Any) -> bool:
    prompt = (
        f"You are grading a bioinformatics answer.\n\n"
        f"Expected answer (rubric): {rubric}\n\n"
        f"Student answer: {predicted}\n\n"
        "Is the student's answer correct? Reply with exactly 'YES' or 'NO'."
    )
    try:
        if hasattr(client, "chat"):
            # Provider ABC path (harness.llm)
            judge_model = getattr(client, "judge_model", "") or "claude-haiku-4-5-20251001"
            response = client.chat(
                model=judge_model,
                system="",
                messages=[{"role": "user", "content": [{"type": "text", "text": prompt}]}],
                tools=[],
                max_tokens=10,
            )
            verdict = response.text.strip().upper()
        else:
            # Raw anthropic.Anthropic backwards-compat path
            response = client.messages.create(
                model="claude-haiku-4-5-20251001",
                max_tokens=10,
                messages=[{"role": "user", "content": prompt}],
            )
            verdict = response.content[0].text.strip().upper()
        return verdict.startswith("YES")
    except Exception:
        return False
```

The `hasattr(client, "chat")` check distinguishes the two paths at runtime.
The new `Provider.chat()` path reads `client.judge_model` (set by `build_provider()`)
to determine which model to use for judging. When `provider == "groq"`, for
example, `judge_model` defaults to the same model being evaluated (e.g.,
`llama-3.3-70b-versatile`), avoiding the need for a separate Anthropic API key
just for scoring.

The `max_tokens=10` ceiling is intentional: the judge only needs to emit `YES`
or `NO`. A tight ceiling prevents verbose judge output from increasing costs.

## 12. Named Provider: Groq

Groq is a cloud inference service that uses LPU (Language Processing Unit) hardware
to achieve very low latency (often 500–1000 tokens/second). Its API is
OpenAI-compatible, making `OpenAIProvider` the right adapter.

> **📦 LPU (Language Processing Unit)**
> Groq's LPU is a custom silicon chip designed specifically for sequential,
> memory-bandwidth-bound inference workloads like autoregressive language model
> generation. Unlike GPUs (Graphics Processing Units), which are optimised for
> parallel matrix operations in training, LPUs can stream generated tokens much
> faster because they have very high memory bandwidth.
> Further reading: [Groq LPU architecture blog](https://groq.com/technology/)

Three things make `groq` a named provider rather than just another
`--provider openai --api-base-url ...` call:

1. **Automatic base URL:**
   ```python
   _DEFAULT_BASE_URLS = {
       "groq": "https://api.groq.com/openai/v1",
       ...
   }
   ```

2. **Named environment variable:**
   ```python
   _API_KEY_ENV_VARS = {
       "groq": "GROQ_API_KEY",
       ...
   }
   ```

3. **`build_provider` routing:** `provider == "groq"` falls into the `else` branch
   (same as `"openai"`) and becomes `OpenAIProvider(api_key, base_url)`.

To use Groq:
```bash
# .env
GROQ_API_KEY=gsk_...

# CLI
python scripts/run_eval.py \
  --provider groq \
  --model llama-3.3-70b-versatile \
  --dataset preview --n-attempts 1
```

For Cerebras or any other OpenAI-compatible provider without a named shortcut,
use `--provider openai` with explicit flags:
```bash
python scripts/run_eval.py \
  --provider openai \
  --model qwen3-235b-a22b-instruct-2507 \
  --api-base-url https://api.cerebras.ai/v1 \

         │           └─► openai.OpenAI(api_key, base_url="https://api.groq.com/openai/v1")
         │
         └─► _run_problem(problem, config, client, ...)
               │
               ├─► cost_before = cost_tracker.total_cost_usd    ← snapshot
               │
               ├─► AgentRun(client=OpenAIProvider, ...).run()
               │     └─► _loop():
               │           while True:
               │             │
               │             ├─► client.chat(model, system, messages, tools, max_tokens)
               │             │     └─► OpenAIProvider.chat()
               │             │           ├─► anthropic_to_openai_messages(messages, system)
               │             │           │     ├─► prepend {"role":"system",...}
               │             │           │     ├─► user text blocks → {"role":"user","content":"..."}
               │             │           │     ├─► tool_result blocks → {"role":"tool","tool_call_id":...}
               │             │           │     └─► assistant blocks → {"role":"assistant","tool_calls":[...]}
               │             │           │
               │             │           ├─► [anthropic_tool_to_openai(t) for t in tools]
               │             │           │     └─► input_schema → parameters
               │             │           │
               │             │           ├─► openai.OpenAI.chat.completions.create(...)
               │             │           │     ↕ HTTPS to https://api.groq.com/openai/v1
               │             │           │
               │             │           ├─► [happy path] openai_response_to_llm_response(response)
               │             │           │     ├─► finish_reason → stop_reason
               │             │           │     ├─► msg.tool_calls → LLMToolCall list
               │             │           │     ├─► [fallback] _parse_llama_text_tool_call(msg.content)
               │             │           │     └─► build raw_content as Anthropic-format dicts
               │             │           │
               │             │           └─► [BadRequestError] extract failed_generation
               │             │                 └─► _parse_llama_text_tool_call(failed_gen)
               │             │
               │             ├─► cost_tracker.add(input, output, cache_read)
               │             ├─► messages.append({"role":"assistant", "content": raw_content})
               │             │
               │             ├─► if stop_reason == "end_turn": return AgentResult(success)
               │             │
               │             └─► if stop_reason == "tool_use":
               │                   for tool_call in response.tool_calls:
               │                     container.exec_command(tool_call.input["command"])
               │                     messages.append({"role":"user","content":[tool_result]})
               │                     # → next iteration converts tool_result back to OpenAI format
               │
               ├─► cost_usd = cost_tracker.total_cost_usd - cost_before   ← delta
               │
               ├─► score_answer(predicted, rubric, client)
               │     └─► _llm_judge(predicted, rubric, client)
               │           └─► client.chat(model=judge_model, ...)    ← same OpenAIProvider
               │                 └─► "YES" or "NO"
               │
               └─► attempt_record["cost_usd"] = cost_usd
                     └─► scores.json
```

## 15. Wire-Format Conversion Reference

### 15.1 Message history conversion

| Anthropic internal format | OpenAI wire format |
|---|---|
| `{"role":"user","content":[{"type":"text","text":"...","cache_control":{...}}]}` | `{"role":"user","content":"..."}` — `cache_control` stripped |
| `{"role":"user","content":[{"type":"tool_result","tool_use_id":"id","content":"..."}]}` | `{"role":"tool","tool_call_id":"id","content":"..."}` — split into separate message |
| `{"role":"assistant","content":[TextBlock(type="text",text="..."), ToolUseBlock(type="tool_use",id,name,input)]}` | `{"role":"assistant","content":"...","tool_calls":[{"id":...,"type":"function","function":{"name":...,"arguments":"<json string>"}}]}` |

### 15.2 Tool definition conversion

| Anthropic format | OpenAI format |
|---|---|
| `{"name":"bash","description":"...","input_schema":{"type":"object",...}}` | `{"type":"function","function":{"name":"bash","description":"...","parameters":{"type":"object",...}}}` |

Key difference: `input_schema` → `parameters`; outer wrapper `{"type":"function","function":{...}}` added.

### 15.3 Response conversion

| OpenAI response field | LLMResponse field | Notes |
|---|---|---|
| `choices[0].finish_reason == "tool_calls"` | `stop_reason = "tool_use"` | |
| `choices[0].finish_reason == "stop"` | `stop_reason = "end_turn"` | |
| `choices[0].message.content` | `text` | |
| `choices[0].message.tool_calls[i].id` | `tool_calls[i].id` | |
| `choices[0].message.tool_calls[i].function.name` | `tool_calls[i].name` | |
| `choices[0].message.tool_calls[i].function.arguments` | `tool_calls[i].input` | JSON-decoded |
| `usage.prompt_tokens` | `usage.input_tokens` | |
| `usage.completion_tokens` | `usage.output_tokens` | |
| `usage.prompt_tokens_details.cached_tokens` | `usage.cache_read_tokens` | May be absent |

## 17. Testing the Adapter

**File:** [tests/test_agent_helpers.py](../../tests/test_agent_helpers.py)

The `TestLLMAdapter` class tests the format conversion helpers in isolation
(no network calls, no Docker):

```python
# tests/test_agent_helpers.py  (TestLLMAdapter excerpts)
class TestLLMAdapter(unittest.TestCase):

    def test_system_prepended(self):
        msgs = anthropic_to_openai_messages([], "sys")
        self.assertEqual(msgs[0], {"role": "system", "content": "sys"})

    def test_cache_control_stripped(self):
        msgs = anthropic_to_openai_messages([
            {"role": "user", "content": [
                {"type": "text", "text": "hi", "cache_control": {"type": "ephemeral"}}
            ]}
        ], "")
        self.assertEqual(msgs[0]["content"], "hi")   # cache_control gone

    def test_tool_result_becomes_role_tool(self):
        msgs = anthropic_to_openai_messages([
            {"role": "user", "content": [
                {"type": "tool_result", "tool_use_id": "id1", "content": "output"}
            ]}
        ], "")
        self.assertEqual(msgs[0]["role"], "tool")
        self.assertEqual(msgs[0]["tool_call_id"], "id1")

    def test_parse_llama_slash_format(self):
        text = '<function/bash>{"command": "ls"}'
        tc = _parse_llama_text_tool_call(text)
        self.assertEqual(tc.name, "bash")
        self.assertEqual(tc.input, {"command": "ls"})

    def test_parse_llama_equals_format(self):
        text = '<function=bash[]{"command": "echo hi"}></function>'
        tc = _parse_llama_text_tool_call(text)
        self.assertEqual(tc.name, "bash")
        self.assertEqual(tc.input, {"command": "echo hi"})
```

## 19. Glossary of Acronyms

| Acronym | Full form | Context |
|---|---|---|
| **ABC** | Abstract Base Class | Python pattern (`abc.ABC`) for defining required method contracts on subclasses |
| **API** | Application Programming Interface | The HTTP interface used to send prompts and receive completions from LLM providers |
| **GPU** | Graphics Processing Unit | Hardware accelerator used in most cloud LLM inference; high matrix-multiply throughput |
| **MaaS** | Models as a Service | Azure AI Foundry's pay-per-token serverless deployment tier; no dedicated GPU VM required |
| **JSON** | JavaScript Object Notation | Text-based data serialisation format; the tool call `arguments` field is a JSON-encoded string |
| **KV cache** | Key-Value cache | The intermediate attention-layer state cached between API calls by Anthropic's prompt cache feature |
| **LLM** | Large Language Model | The AI models driving the agent (Claude, Llama, Qwen, etc.) |
| **LPU** | Language Processing Unit | Groq's custom chip for high-throughput sequential inference (tokens/second) |
| **OpenAI-compat** | OpenAI-compatible | An API that implements the same REST contract as OpenAI's `POST /v1/chat/completions` endpoint |
| **Pydantic** | — (not an acronym; named after pydantic validation) | Python library for data validation using type annotations; the Anthropic SDK returns Pydantic model instances |
| **SDK** | Software Development Kit | `anthropic` (Python) and `openai` (Python) are the two SDKs used in this project |
| **UUID** | Universally Unique Identifier | A 128-bit random identifier; `uuid.uuid4().hex[:8]` produces synthetic tool call IDs |
| **REST** | Representational State Transfer | Architectural style for HTTP APIs; both Anthropic and OpenAI APIs are REST-based |
