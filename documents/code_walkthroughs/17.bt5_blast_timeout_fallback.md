## 1. Background

BT-1..4 (PR #89, 2026-05-28) addressed two compounding BLAST failure modes observed in
RERUN-6 trajectories:

- **BT-1**: enforced a hard 1500 bp query-size cap at dispatch time, preventing the
  full-genome BLAST spiral.
- **BT-2**: corrected the system prompt's false claim that "there is no wall-clock limit."
- **BT-3**: added elapsed wall-clock time to the step footer so the agent could see
  budget consumption.
- **BT-4**: rewrote `SKILLS/blast-search/SKILL.md` to open with "Always start with ≤500 bp."

After those four fixes, the hb002 re-validation was run (2026-05-29, gpt-oss-120b,

## 2. Failure Analysis

Attempt 0 trajectory (`results/gpt-oss-hb002-revalidation/trajectories/problem-hb002_attempt-0.*`):

| Step | Event |
|------|-------|
| 1–5 | Agent inspects genome file, extracts 474 bp 16S region |
| 6 | `blast_search` call → rc=-1 after 600s (NCBI server load) |
| 7 | Agent reads rc=-1 message: "Use ≤1500 bp for remote BLAST" |
| 8 | Agent extracts 150 bp sub-region, retries BLAST |
| 9 | `blast_search` call → rc=-1 after 600s again |

Two problems caused step 7 to give unhelpful guidance:

**Problem A — stale rc=-1 message.** BT-1 already enforced the 1500 bp cap at dispatch.
The rc=-1 message still said "Use ≤1500 bp for remote BLAST" — advice that BT-1 had made
irrelevant. After two timeouts on queries that were already within the cap, the agent had
no new information from the message.

**Problem B — system prompt §3a too vague.** The phrase "switch to a local approach" was
intended to mean "try a different tool that doesn't need a network connection" but the
agent interpreted it as license to download a reference genome and run alignment — a
category error.

## 3. The Two BLAST Failure Modes

Two BLAST failure modes are easy to conflate but require completely different recovery
paths. Mixing them up puts the wrong guidance in the wrong error branch.

### Mode A — rc=0, Species = N/A

BLAST ran successfully and found hits with accession IDs. The `sscinames` NCBI column is
absent for newer assemblies (a known NCBI indexing gap, not a BLAST failure).

**Correct recovery:** Read the top accession from
`/workspace/scratch/blast_results.txt` and fetch the organism name via NCBI Entrez:

```bash
curl -s "https://eutils.ncbi.nlm.nih.gov/entrez/eutils/efetch.fcgi?db=nuccore&id=<ACC>&rettype=gb&retmode=text" | head -20
```

This works because a successful BLAST hit exists and returned an accession. The
`blast-search.md §8` SKILL covers this case.

### Mode B — rc=-1, no results

BLAST network stalled. No hits, no accession IDs. The 600s per-command timeout fired.

**Correct recovery:**
1. Try `Bio.Blast.NCBIWWW.qblast()` — the Python NCBI BLAST API uses a different
   HTTP connection and timeout path from the command-line `-remote` flag.
2. Or `sleep 290` (5 minutes, one step) and retry with a ≤150 bp probe.

`curl efetch` is wrong here — it requires an accession ID from a successful hit, which
doesn't exist when BLAST timed out.

> **📦 Bio.Blast.NCBIWWW.qblast()**
> Biopython's NCBI BLAST web service client. Connects to
> `https://blast.ncbi.nlm.nih.gov/blast/Blast.cgi` via HTTP POST. Uses its own
> connection management independent of the `blastn -remote` flag, so it can succeed
> when the command-line remote path is stalling. Requires Biopython (`pip install
> biopython`, already installed in the container). Typical call:
> ```python
> from Bio.Blast import NCBIWWW, NCBIXML
> result_handle = NCBIWWW.qblast("blastn", "nt", query_seq)
> records = list(NCBIXML.parse(result_handle))
> top = records[0].alignments[0].title if records[0].alignments else "No hits"
> print(top)
> ```
> Further reading: https://biopython.org/docs/latest/api/Bio.Blast.html#Bio.Blast.NCBIWWW.qblast

## 4. Fix 1 — `_BLAST_RC_MESSAGES[-1]` in `harness/agent.py`

**File:** [`harness/agent.py`](../../harness/agent.py)

`_BLAST_RC_MESSAGES` is a dict mapping BLAST exit codes to diagnostic strings that are
prepended to every `blast_search` tool result. The rc=-1 entry is the network-stall branch.

**Before (stale after BT-1):**
```python
-1: "Timed out — query too large or network stall. Use ≤1500 bp for remote BLAST.",
```

**After (BT-5):**
```python
-1: (
    "Network stall (query was already ≤1500 bp — size is not the issue). "
    "Check /workspace/scratch/blast_results.txt for any partial hits. "
    "If none: try Bio.Blast.NCBIWWW.qblast() in Python, "
    "or sleep 290 (5 min) and retry with a ≤150 bp query. "
    "Do not switch to alternative alignment tools (e.g. minimap2) until "
    "a short BLAST query returns results. "
    "See /workspace/skills/blast-search.md §9 for the qblast() recipe."
),
```

Key decisions:
- **Opens by acknowledging the cap is already enforced** — "size is not the issue" so
  the agent doesn't waste a step shrinking a query that BT-1 would already have blocked.
- **Points to the scratch file first** — partial hits may exist even on a timeout;
  checking the file costs nothing and may provide the accession the agent needs.
- **Gives the qblast() recipe pointer** — keeps the detailed code in the SKILL file
  (blast-search.md §9) rather than embedding it in the error message.
- **Explicitly names minimap2** as the anti-pattern to avoid, because that is exactly
  what attempt 0 did.

## 5. Fix 2 — System Prompt §3b in `prompts/system.txt`

**File:** [`prompts/system.txt`](../../prompts/system.txt)

§3b advises agents to use the `blast_search` tool over raw bash. BT-5 appends a new
paragraph to §3b that fires when the tool returns rc=-1:

```
If `blast_search` returns rc=-1 (network timeout) and
`/workspace/scratch/blast_results.txt` contains no hits, do not switch to
alternative alignment approaches (e.g. downloading a reference genome and running
minimap2 — alignment percentage is not a species identity metric). Instead:
(a) try `Bio.Blast.NCBIWWW.qblast()` via Python (Biopython is installed; see
`/workspace/skills/blast-search.md` §9 for the recipe), or
(b) `sleep 290` in bash (5 minutes, counts as one step) then retry with a ≤150 bp
query. Do not submit longer queries until a ≤150 bp probe succeeds.
```

**Why §3b and not §3a:** §3a handles the "empty output does not mean tool missing" case
(rc=0 + empty stdout). The timeout fallback is a separate issue — the tool ran, NCBI's
server stalled. Keeping them separate makes each rule easier to read without the other.

**Why "alignment percentage is not a species identity metric" is spelled out:**
The hb002 attempt-0 failure was specifically caused by the agent treating minimap2's
PAF `de` field as a species-identity score. The explicit parenthetical closes the gap
between the abstract rule ("don't switch to alternative alignment") and the specific
anti-pattern the agent used.

## 6. Why efetch Was Excluded

The original plan (before user review) included `curl efetch` as a timeout fallback in
both the error message and the system prompt. The user explicitly removed it with the
following rationale: **efetch guidance is problem-specific**.

`curl efetch` works only when BLAST returned a hit with an accession. That is the N/A
species case (Mode A above) — not the timeout case (Mode B). Putting efetch guidance in
the rc=-1 message would mislead agents dealing with a genuine timeout. The `blast-search.md §8`
SKILL already covers the N/A species case, and a dedicated efetch SKILL may be written
separately.

This is an example of a lesson documented in §L-32: the two failure modes require
different fallbacks, and conflating them produces guidance that is wrong for one mode.

def test_rc_negative_one_timeout(self):
    result = _summarize_blast_output("", rc=-1)
