## 1. Background

RERUN-6 (Qwen3/Cerebras, walkthrough 13) revealed three layered failures on hb002: the
BLAST binary was absent from the Docker image, the harness silently discarded empty BLAST
output, and the system prompt gave incorrect guidance. PRs #83 (BF-1..4), #85 (IO-1),
#87 (BP-1..5), and #89/91 (BT-1..5) addressed all three layers over subsequent sessions.

RERUN-7 was the first end-to-end validation run after all those fixes landed. The model
was switched from Qwen3 (deprecated by Cerebras on 2026-05-27) to `gpt-oss-120b`, which
is the current default Cerebras model.

Two additional facts made RERUN-7 a broader test than RERUN-6:
- RERUN-6 only ran three problems (hb002, hb022, hb053). RERUN-7 ran all five preview
  problems, adding hb020 (crystal structure) and recqgsfxqqodhjens (ChIP-seq TF) for
  the first time.
- RERUN-7 used `reasoning_effort=high`, surfacing the model's chain-of-thought in the
  trajectory JSONL (field: `reasoning`, added in RV-1..4).

## 2. Benchmark Configuration

```bash
python3.12 scripts/run_eval.py \
  --problem-ids hb002,hb020,hb022,hb053,recqgsfxqqodhjens \
  --n-attempts 5 \
  --provider openai \
  --model gpt-oss-120b \
  --api-base-url https://api.cerebras.ai/v1 \
  --api-key "$CEREBRAS_API_KEY" \
  --reasoning-effort high \
  --critic-injection-points after_final_answer \
  --critic-injection-points after_critic_response \
  --results-dir results/gpt-oss-rerun7-5x5
```

Key parameters:

| Parameter | Value | Notes |
|-----------|-------|-------|
| Model | `gpt-oss-120b` | Cerebras default after Qwen3 deprecation |
| Provider | `openai` (OpenAI-compat) | Cerebras endpoint via `--api-base-url` |
| `reasoning_effort` | `high` | Cerebras extended thinking; stored in JSONL |
| Critic | two-round (`after_final_answer` + `after_critic_response`) | Same as RERUN-6 |
| `--n-attempts` | 5 | Each problem run 5 independent times |
| Max steps | 100 (default) | Agent can take up to 100 bash tool calls per attempt |
| Step timeout | 600s per command | Raised from 300s in BT-1 to accommodate BLAST |
| Wall-clock limit | 1800s per attempt | Enforced by `run_timeout_seconds` in `RunConfig` |

> **📦 Cerebras OpenAI-compatible API**
> Cerebras exposes its inference API with the same request/response format as the OpenAI
> Chat Completions API, so the harness uses `--provider openai` with a custom
> `--api-base-url`. The `reasoning_effort` parameter is a Cerebras extension that
> triggers extended thinking and populates `msg.reasoning` on each response; the harness
> reads this via `LLMResponse.reasoning` (added in RV-4, PR #89).

> **📦 pass@1 vs pass@5**

## 4. Per-Problem Breakdown

### 4.1 hb002 — Bacterial Species ID (5/5 ✅)

**Question:** What bacteria is found in this sequenced dataset? Provide the bacteria's
scientific name as the answer.

**Answer:** Bacillus licheniformis

**Why it now works:** RERUN-6 got 0/5 because BLAST was not installed in the Docker image.
BF-1 (PR #83) added `blast` to the Dockerfile's micromamba install. The BT-1..5 series
(PRs #89, #91) then addressed timeout handling: a 1500 bp query-size cap, corrected
wall-clock messaging, and a `qblast()` fallback for network stalls.

**Trajectory pattern:** Each attempt ran 9–25 steps in 2–13 minutes. The agent used
`blast_search` to BLAST the anonymous genome sequence, obtained `Bacillus licheniformis`
in the top hit, and submitted the answer. No BLAST timeouts occurred in any attempt.

**Critic behaviour:** Critic fired in attempt 3 (round 2: "concerns resolved") and attempt 4
(critic not fired — critic injection at `after_final_answer` produced no critique). The
two-round critic had no negative effect on correct answers.

### 4.2 hb020 — Crystal Structure Organism (4/5 ✅)

**Question:** What organism does this crystal structure belong to? Provide the answer
using binomial nomenclature.

**Answer:** Homo sapiens

**Data:** An mmCIF/CIF crystallographic structure file.

**Pattern:** The agent reads the CIF file metadata, which typically contains an
`_entity_src_nat.pdbx_organism_scientific` or `_citation_author.name` field. In 4 of
5 attempts, it found this metadata and returned *Homo sapiens* directly.

**Failure (attempt 0):** Predicted *Pan troglodytes* (chimpanzee). The agent may have
misread an `_exptl_crystal_grow` block or organism field that contained primate sequence
data used for comparison, or conflated the expression host with the source organism.
The critic fired and noted "No unverified assumptions were identified — the agent did
not make any explicit claim about the organism in the provided trajectory," which means
the critic could not detect the error because the agent did not narrate its reasoning
step clearly. Steps: 43, time: 33 min.

**Recovery:** All four subsequent attempts correctly read the CIF metadata. pass@5 = True;
the problem is reliably solvable.

### 4.3 recqgsfxqqodhjens — TF Binding Sites (5/5 ✅)

**Question:** Identify the transcription factor whose binding sites are represented by
the provided peaks data. Provide the transcription factor's gene symbol.

**Answer:** CTCF

**Data:** A BED file of ChIP-seq peak coordinates.

**Approach:** The agent used the `chipseq-tf-identification` SKILL (`/workspace/skills/
chipseq-tf-identification.md`) to run motif enrichment analysis on the peak sequences.
CTCF has a highly distinctive CCCTC motif that is immediately identifiable via MEME or
HOMER. The agent typically fetched reference genome sequences for the peak intervals,
ran motif analysis, and matched to the CTCF canonical motif.

**Step counts:** 53–92 steps per attempt (18–34 minutes). The higher step counts reflect
genome sequence retrieval (downloading UCSC hg38 intervals) before motif analysis.

**Operational note:** This problem was not included in RERUN-6. The harness only ran
hb002, hb022, and hb053 in RERUN-6 because the benchmark was launched with
`--problem-ids hb002,hb022,hb053`. RERUN-7 was intended to cover all five problems from
the start; the first run accidentally omitted hb020 and recqgsfxqqodhjens and had to be
resumed. See §7 for the full operational incident.

> **📦 CTCF and ChIP-seq TF identification**
> CTCF (CCCTC-binding factor) is the most abundant transcriptional insulator protein
> in mammals. It has a highly conserved 11-zinc-finger DNA binding domain with a
> canonical motif (CCGCGNGGNGGCAG) that is among the most distinctive of any TF.
> ChIP-seq peaks for CTCF are routinely identified by submitting peak sequences to a
> motif enrichment tool (HOMER, MEME-ChIP, JASPAR) and matching the top enriched motif
> against the JASPAR database.

### 4.4 hb022 — Erastin-Treated Samples (0/5 ❌)

**Question:** This dataset contains gene expression profiles from human pancreatic cancer
cell lines. The samples have been anonymized as Sample_01…Sample_16 and divided into two
experimental conditions (Condition_X and Condition_Y). One condition represents cells
treated with the drug Erastin. Which samples correspond to the Erastin-treated group?

**Correct answer:** [Sample_01, Sample_02, Sample_03, Sample_04, Sample_05, Sample_06,
Sample_07, Sample_08]

**Predicted answer (all 5 attempts):** [Sample_09, Sample_10, Sample_11, Sample_12,
Sample_13, Sample_14, Sample_15, Sample_16]

**human_solvable:** False

#### Failure analysis

The agent consistently clusters the 16 samples into two groups of 8 via PCA or
hierarchical clustering — that part is correct. It then assigns the clusters by looking
at expression of known Erastin-responsive genes.

The critical gene is **SLC7A11** (also known as xCT, the cystine/glutamate antiporter):

```
SLC7A11-AS1 expression:
  Sample_01–08:  −0.37, −1.55, −0.34, −1.66, −0.57, −1.73, −0.31, −1.91  (lower)
  Sample_09–16:  +0.57, +0.43, +0.26, +0.37, +0.25, +0.33, +0.34, +0.45  (higher)
```

The agent assumes SLC7A11 should be *higher* in Erastin-treated cells (reasoning:
"Erastin inhibits SLC7A11 → cells upregulate it as compensation"), so it assigns
Sample_09–16 as Erastin-treated. But the correct group is Sample_01–08, where SLC7A11
is lower — consistent with direct pharmacological inhibition of the transporter leading
to reduced gene expression.

This is a **model-level knowledge error** about the direction of SLC7A11 regulation
under Erastin treatment, not a harness defect. RERUN-6/Qwen3 got 3/5 correct on this
problem, suggesting Qwen3 had more accurate Erastin biology priors.

Since hb022 is `human_solvable=False`, this failure does not indicate a solvable gap
in the harness. The problem was apparently included in the benchmark as a "hard negative"
to test whether models can resist guessing — and gpt-oss-120b cannot.

> **📦 Erastin and ferroptosis**
> Erastin is a small molecule that induces ferroptosis (iron-dependent oxidative cell death)
> by pharmacologically inhibiting the cystine/glutamate antiporter system Xc-, encoded by
> SLC7A11 (xCT subunit). Erastin blocks cystine uptake, depleting intracellular glutathione
> (GSH) and inactivating GPX4, which leads to unchecked lipid peroxidation and cell death.
> Gene expression signatures of Erastin treatment include upregulation of PTGS2 (COX-2),
> CHAC1, and HMOX1, and downregulation of SLC7A11 in some contexts.

### 4.5 hb053 — Brachypodium Stress Type (0/5 ❌)

**Question:** The transcriptome of Brachypodium distachyon was sequenced under a specific
stress. Based on the sequences of differentially expressed genes, what was the perturbation?
Provide the stress type as a short descriptive phrase.

**Correct answer:** Heat stress

**Predicted answers:** pathogen stress, drought stress, phosphate starvation (varying per attempt)

**human_solvable:** False

#### Failure analysis

The data file is `B.distachyon_DEG_scrubbed.txt` — a FASTA file of differentially
expressed gene sequences with gene IDs removed ("scrubbed"). The agent must:
1. BLAST each sequence to identify the gene
2. Map identified genes to known stress pathways
3. Identify which stress type is most enriched

The agent correctly identifies the FASTA-based approach and attempts BLAST. However,
it consistently arrives at wrong stress categories:

- **pathogen/drought/phosphate**: These stress categories have large, overlapping GO
  term sets. Many stress-responsive genes (e.g. MAPK cascades, peroxidases, transcription
  factors) are induced across multiple stresses.
- **Heat stress signature not recognised**: Heat stress is defined by induction of heat
  shock proteins (HSPs: HSP90, HSP70, HSP40, HSP101) and heat shock factors (HSF1, HSF3).
  In Brachypodium, the orthologues have different gene IDs than their Arabidopsis or human
  counterparts. The agent may be failing to match BLAST hits to the correct heat shock
  gene family, or the BLAST results for scrubbed sequences may be too ambiguous.

The problem is `human_solvable=False`, meaning even human experts failed to solve it
reliably. The harness cannot be expected to fix this without domain-specific knowledge
of Brachypodium heat stress gene identifiers.

> **📦 Brachypodium distachyon as a grass model**
> Brachypodium distachyon is a small temperate grass used as a model organism for
> cereal genomics. Unlike Arabidopsis thaliana, Brachypodium gene symbols often do not
> follow the AT-prefix naming convention. Heat shock proteins in Brachypodium are
> annotated as BdHSP* or identified via BLAST to Triticum/Hordeum HSP orthologues.
> The NCBI gene annotation for Brachypodium Bd21-3 is the reference genome used for
> most functional studies.

## 6. Trajectory Analysis Highlights

Full per-attempt analysis is in `results/gpt-oss-rerun7-5x5/trajectories/
trajectory_analysis.md` (generated by `scripts/analyze_trajectories.py`).

Selected observations from 25 attempts:

**API rate-limit backoffs:**
- hb002 attempt 2: 1 backoff (1 min wait) — Cerebras 429
- hb002 attempt 4: 1 backoff (1 min wait)
- hb022 attempts 2–3: 2 backoffs each (2 min wait)
- All other attempts: 0 backoffs

Rate limiting remained mild — never more than 2 backoffs per attempt, consistent with
the ≤3/s BLAST rate-limiting added in BP-3 (PR #87) reducing total API call frequency.

**Critic effectiveness:**
- hb002 attempt 3: critic fired (round 2 returned "concerns resolved")
- hb020 attempts 0–1: critic fired but gave "No unverified assumptions identified"
  — could not detect the Pan troglodytes error because the agent did not narrate its
  organism-identification reasoning step explicitly.
- hb053 attempts 2–3: critic fired and also gave "No unverified assumptions identified"
  — the agent's wrong stress-type guess was not flagged because the critic only looks
  for unverified claims, not factual errors in biological interpretation.

**Critique of the critic on hard problems:** On hb020/hb053 failures, the critic failed
to catch the error. This is a known limitation of the CITATION GATE approach (CA-1..5,
PR #80): the critic requires the agent to make an explicit verifiable claim. When the
agent arrives at a wrong answer via opaque clustering/analysis code rather than a stated
assumption, the critic has nothing to cite and flags nothing.

**Step counts:**
- hb053 had the highest step counts: 26–91 steps, up to 47 min per attempt.
  Attempts 1 and 3 used 89 and 91 steps respectively (near the 100-step limit),
  suggesting the agent was iterating through many BLAST queries without converging.
- recqgsfxqqodhjens also ran long: 53–92 steps, 8–34 min, likely due to genome
  sequence retrieval for motif analysis.

## 7. Operational Notes

### Run command flags — three errors on first launch

The RERUN-7 launch hit three CLI flag errors before the run started (now documented
in L-34, code-learnings SKILL):

1. `--problems` → correct flag is `--problem-ids`
2. `--attempts` → correct flag is `--n-attempts`
3. Space-separated IDs → must be comma-separated: `--problem-ids hb002,hb022,hb053`

Additionally, the `openai` provider looks for `OPENAI_API_KEY` but Cerebras uses
`CEREBRAS_API_KEY` — `--api-key "$CEREBRAS_API_KEY"` must be passed explicitly.

### Two-stage run (3 problems, then 2 more)

The first launch specified only `hb002,hb022,hb053`, omitting hb020 and recqgsfxqqodhjens.
This was discovered after the first run completed. A second run was launched with all 5
problems and `--resume`, which correctly skipped the already-completed 15 attempts and
ran only the 10 new ones.

### Docker Desktop crash mid-run

Docker Desktop crashed during recqgsfxqqodhjens attempt 3 (0-indexed: attempt-2).
The error was "Error while fetching server API version: Expecting value: line 1 column 1".
The attempt-2 JSONL was created but empty. `is_attempt_complete()` in `harness/logger.py`
checks for a status record in the JSONL, so an empty file correctly returns `False` and
is treated as incomplete by `--resume`.

After restarting Docker Desktop, the run was resumed and attempts 3–5 completed correctly.

### is_attempt_complete logic (safe for empty files)

```python
# harness/logger.py
def is_attempt_complete(results_dir, problem_id, attempt):
    path = Path(results_dir) / "trajectories" / f"problem-{problem_id}_attempt-{attempt}.jsonl"
    if not path.exists():
        return False
    with path.open() as f:
        for line in f:
            rec = json.loads(line)
            if rec.get("role") == "status" and rec.get("data", {}).get("status") in (
                "success", "max_steps", "timeout", "token_limit", "resource_abort"
            ):
                return True
    return False
```

An empty file has no lines, so the loop exits immediately and returns `False`. This is
the correct behaviour for crash-recovery: an empty JSONL means the attempt did not
complete and should be re-run.
