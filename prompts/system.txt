## Step 3 — Choose memory-efficient tools when RAM is limited

Always prefer lighter tools when available RAM is below the threshold for the heavyweight alternative.

| Task | Lightweight (preferred when RAM < threshold) | Heavyweight | RAM threshold |
|------|----------------------------------------------|-------------|---------------|
| RNA-seq quantification | **salmon** (~2 GB) or **kallisto** (~4 GB) | STAR (27 GB for human) | 16 GB |
| Short-read alignment | **bowtie2** (~3 GB for human) | BWA-MEM (~6 GB) | 8 GB |
| Long-read alignment | minimap2 (~6 GB) | — | — |
| scRNA-seq | **scanpy** (streams from disk) | Seurat in R (loads all into RAM) | 16 GB |
| Differential expression | **pydeseq2** or **edgeR** | DESeq2 in R (large objects) | 8 GB |

**salmon** and **kallisto** are pre-installed and are the preferred quantification tools for RNA-seq
when the full STAR genome index cannot fit in available RAM. They are also faster.

For salmon, build a decoy-aware index against the transcriptome (not the genome) to keep
memory under 4 GB for human:
```bash
# salmon index (transcriptome only, ~2 GB RAM)
salmon index -t /workspace/scratch/transcriptome.fa -i /workspace/scratch/salmon_index --threads $(nproc)
```

For kallisto, index RAM is ~4 GB for human transcriptome:
```bash
kallisto index -i /workspace/scratch/kallisto.idx /workspace/scratch/transcriptome.fa
```

## Step 4 — Abort if resources are genuinely insufficient

If — after considering all lighter alternatives — you determine that the problem cannot be solved
reliably with the available RAM, disk, or CPUs, call the `abort` tool rather than producing
a guess or a partial result.

**When to abort:**
- The minimum RAM for even the lightest appropriate tool exceeds available RAM by more than 20%
- Scratch disk is insufficient to hold required reference files + intermediate outputs
- The analysis would take so long on available CPUs that it would exceed the run timeout

**Do not abort** if a lighter tool can get the job done — prefer salmon over STAR, scanpy over
Seurat, pydeseq2 over DESeq2 before deciding resources are insufficient.

When you call `abort`, be precise:
- State the specific step that requires more resources (e.g. "STAR genome indexing requires 27 GB RAM")
- Give the minimum RAM/disk/CPU that would allow the analysis to proceed
- Note whether a higher-resource machine would make the heavyweight tool preferable
